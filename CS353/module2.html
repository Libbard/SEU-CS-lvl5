The Analysis Framework

Two Types of Efficiency

  • Time Efficiency: How fast the algorithm runs (Time Complexity).
  • Space Efficiency: Memory units required for algorithm + input/output (Space Complexity).

Measuring Input Size ($n$)

Input size depends on the problem type :

  • Polynomials: Degree of polynomial or number of coefficients.
  • Matrices: Dimensions ($n \times n$).
  • Primality Check: Number of bits $b = \lfloor \log_2 n \rfloor + 1$ (NOT the number value itself).

The "Basic Operation"

We DO NOT measure time in seconds or milliseconds because that depends on the computer speed, compiler, and quality of code .

Instead, we count the Basic Operation: the operation contributing most to running time (usually the most frequent one inside the innermost loop).

Worst, Best, & Average Cases

Worst-Case

The input that makes the algorithm run the longest. It provides an Upper Bound guarantee. The algorithm will never take longer than this .

$C_{worst}(n)$

Best-Case

The input that makes the algorithm run the fastest. Usually trivial (e.g., finding the item at index 0) .

$C_{best}(n)$

Average-Case

Based on probabilistic assumptions. Usually lies between Best and Worst. Requires knowing probability distribution of inputs .

$C_{avg}(n)$

Amortized Efficiency: Not a single run, but the average cost over a sequence of operations. Useful when one expensive operation pays for many cheap ones (discovered by Robert Tarjan) .

Asymptotic Notations ($O, \Omega, \Theta$)

1. Big-O Notation $O(g(n))$

Upper Bound. $t(n)$ grows no faster than $g(n)$.

$t(n) \le c \cdot g(n)$ for all $n \ge n_0$

Use for Worst-Case Analysis.

2. Big-Omega Notation $\Omega(g(n))$

Lower Bound. $t(n)$ grows at least as fast as $g(n)$.

$t(n) \ge c \cdot g(n)$ for all $n \ge n_0$

Use for Best-Case Analysis.

3. Big-Theta Notation $\Theta(g(n))$

Tight Bound. $t(n)$ grows at the same rate as $g(n)$.

$c_2 \cdot g(n) \le t(n) \le c_1 \cdot g(n)$

Use for Exact/Average Analysis.

Non-Recursive Analysis

Process :

  1. Decide on input parameter ($n$).
  2. Identify basic operation (innermost loop).
  3. Set up a Summation $\sum$.
  4. Solve the sum to find closed form.

// Example: UniqueElements

$C_{worst}(n) = \sum_{i=0}^{n-2} \sum_{j=i+1}^{n-1} 1$

$= \frac{(n-1)n}{2} \approx \frac{1}{2}n^2 \in \Theta(n^2)$

Recursive Analysis

Process :

  1. Decide on input parameter ($n$).
  2. Identify basic operation.
  3. Set up a Recurrence Relation.
  4. Solve using Backward Substitution.

// Example: Factorial F(n)

$M(n) = M(n-1) + 1$ for $n > 0$

$M(0) = 0$

Result: $M(n) = n$

Empirical Analysis

Used when mathematical analysis is too difficult. Involves generating random inputs, running the actual code, measuring time/count, and plotting results .

The Exam Vault

Professor's Secrets & Trap Avoidance

TRAP: Value vs. Size

For Primality Testing, if the input is $n = 1,000,000$, the input size is NOT $10^6$. It is the number of bits: $b = \log_2(10^6) \approx 20$. This is a classic trick question .

TRAP: Inner Loops

Don't just count the loops. Look at the limits.
Loop $1..n$ inside Loop $1..n$ $\rightarrow O(n^2)$.
Loop $1..n$ inside Loop $1..10$ $\rightarrow O(n)$ (because 10 is constant).

SECRET: The Constant Factor

In Asymptotic notation, constants ($c$) and lower order terms are ignored. $100n + 5 \in O(n^2)$ is technically true (loose bound), but $\Theta(n)$ is the tight (better) answer .

KEY CONCEPT: Backward Substitution

Master the "Method of Backward Substitution" for recursive relations. It is the primary method required for Module 2 exams to prove $M(n)=n$ or similar .
