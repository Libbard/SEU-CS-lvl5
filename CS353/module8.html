Space and Time Trade-Offs

Spending memory to save time. We preprocess inputs or use extra structures to accelerate algorithms from brute force to blazing fast.

Strategies for Trading Space

1. Input Enhancement

Preprocess the problem's input (in whole or part) and store additional info to use later.

  • Counting Sorts
  • String Searching (Horspool, Boyer-Moore)

2. Prestructuring

Process the input to build a data structure that makes accessing elements easier or faster.

  • Hashing
  • Indexing Schemes (B-Trees)

Sorting by Counting

Method A: Comparison-Counting Sort

For each element $A[i]$, count how many elements are smaller than it. This count is its exact position in the sorted array .

for i $\leftarrow$ 0 to n-2 do
  for j $\leftarrow$ i+1 to n-1 do
    if A[i] < A[j]
      Count[j] $\leftarrow$ Count[j] + 1
    else Count[i] $\leftarrow$ Count[i] + 1
// Copy to Result Array S
for i $\leftarrow$ 0 to n-1 do S[Count[i]] $\leftarrow$ A[i]

Complexity

$O(n^2)$

No improvement over simple sorts.

Method B: Distribution Counting Sort

Assume elements come from a small set of integers between $l$ and $u$. We compute frequencies, then cumulative frequencies (distribution), to calculate positions directly .

1 Compute Frequencies ($F$).
2 Compute Distribution ($D$): $D[j] = D[j-1] + F[j]$.
3 Place elements: $S[D[A[i]-l]-1] = A[i]$.

Complexity

$O(n)$

Linear time! (If range is small)

String Matching

Brute force string matching takes $O(nm)$. We can do better by Preprocessing the pattern to know how much to shift when a mismatch occurs.

Horspool's Algorithm

A simplified version of Boyer-Moore. It compares the pattern from Right-to-Left. If a mismatch occurs, it determines the shift size based on the character in the text aligned with the last character of the pattern.

Text: ... B A R B E R ...
Pattern: L E A D E R

Logic: Look at 'B' in Text (aligned with Pattern's end). 'B' is not in Pattern? Shift full length!

The Shift Table Construction

For each character $c$ in the alphabet:

  • If $c$ is NOT in the pattern: Shift by pattern length $m$.
  • If $c$ IS in the pattern: Shift by distance from right end ($m - 1 - k$).
  • Note: Only consider the last occurrence of $c$ (excluding the very last character itself for calculation purposes) .

The Exam Vault

Professor's Secrets & Trap Avoidance

TRAP: Distribution Sort Range

"Is Distribution Counting Sort always linear $O(n)$?"
NO! It depends on the range of values ($k$). The complexity is actually $O(n + k)$. If $k \approx n^2$, the algorithm becomes $O(n^2)$, which is worse than Mergesort.

TRAP: Horspool's Lookup

When a mismatch occurs in Horspool, which character do you look up in the Shift Table?
NOT the mismatched character. You look at the character in the TEXT that is aligned with the LAST character of the pattern.

SECRET: Comparison Counting

Professors teach Comparison-Counting Sort ($O(n^2)$) not because it's useful (it's not), but to prove that simply throwing "extra space" at a problem doesn't automatically solve "time" efficiency. You need the right strategy (like Distribution Counting).

KEY CONCEPT: Worst Case Horspool

Despite being very fast on average ($O(n)$), Horspool's (and Boyer-Moore's) worst case is still $O(nm)$, just like Brute Force. This happens with patterns like "AAAAA" in text "AAAAAAAA".
