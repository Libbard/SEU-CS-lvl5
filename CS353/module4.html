Decrease-and-Conquer

Exploiting the relationship between a problem of size $n$ and a smaller instance to solve it efficiently.

Insertion Sort Topological Sort Binary Search QuickSelect

Three Variations of Reduction

Decrease by Constant

Reduce problem size by a fixed amount (usually 1).

$f(n) \rightarrow f(n-1)$

Ex: Insertion Sort, DFS, BFS

Decrease by Factor

Reduce problem size by a factor (usually 2, i.e., half).

$f(n) \rightarrow f(n/2)$

Ex: Binary Search

Variable Decrease

Size reduction pattern varies at each step.

$f(n) \rightarrow f(?)$

Ex: Euclid's GCD, Selection Problem

Insertion Sort

The Logic

Think of sorting cards in your hand. You pick the next card ($A[i]$) and insert it into the correct position among the already sorted cards to its left ($A[0..i-1]$). This is a recursive idea implemented iteratively (Bottom-Up) .

for i $\leftarrow$ 1 to n-1 do
  v $\leftarrow$ A[i]
  j $\leftarrow$ i - 1
  while j $\ge$ 0 and A[j] > v do
    A[j+1] $\leftarrow$ A[j] // Shift right
    j $\leftarrow$ j - 1
  A[j+1] $\leftarrow$ v // Insert

Worst Case

Reverse sorted array. Each element must move all the way to the start.
$C_{worst}(n) \in O(n^2)$

Best Case

Already sorted array. Only 1 comparison per element.
$C_{best}(n) = n - 1 \in O(n)$

Average Case

Random data. Average $\approx n^2/4$. Still quadratic, but twice as fast as Selection Sort on average .

Topological Sorting

The problem of ordering vertices in a Directed Acyclic Graph (DAG) such that for every edge $u \to v$, $u$ comes before $v$ in the ordering. Used for scheduling tasks with prerequisites .

Method 1: Source Removal

  1. Identify a Source (vertex with in-degree 0).
  2. Delete it and all outgoing edges.
  3. Repeat until graph is empty.
  4. Order of deletion = Topological Sort .

Method 2: DFS Based

  1. Perform DFS traversal.
  2. Note the order in which vertices are popped (dead ends).
  3. Reverse that order.

Binary Search

The ultimate example of efficiency. Reduces problem size by half at every step. Requires a sorted array.

Recurrence Relation:
$C_{worst}(n) = C_{worst}(\lfloor n/2 \rfloor) + 1$
$C_{worst}(1) = 1$
$O(\log_2 n)$

Search Space Halves Every Step

Selection Problem (QuickSelect)

Finding the $k$-th Smallest Element

Can we find the median without sorting the whole array?

Lomuto Partition

Uses Partitioning (like QuickSort). Pick a pivot $p$. Rearrange array so elements $< p$ are left, $> p$ are right.

  • If pivot index $s = k-1$, we found it!
  • If $s > k-1$, look in left part (discard right).
  • If $s < k-1$, look in right part (discard left).
Best/Avg Case $O(n)$
Worst Case $O(n^2)$

The Exam Vault

Professor's Secrets & Trap Avoidance

TRAP: Insertion Sort Efficiency

"Is Insertion Sort always slow?"
No! On an almost sorted array, it runs in $O(n)$ time (Best Case). It is often faster than QuickSort for very small arrays ($n < 20$) .

TRAP: Cycles in Topo Sort

Topological Sort is IMPOSSIBLE if the graph has a Cycle. It only works on DAGs (Directed Acyclic Graphs). If an exam question asks you to topo-sort a graph with a loop, the answer is "No Solution".

SECRET: Binary Search Ceiling

When calculating mid, we usually do $\lfloor (l+r)/2 \rfloor$. If the array size is even, this picks the left middle. Be careful tracing this manually in exams; picking the wrong middle index changes the trace path.

KEY CONCEPT: The Pivot

The efficiency of QuickSelect (and QuickSort) depends entirely on the Pivot. If the pivot splits the array into 0 and $n-1$ elements every time, you hit the $O(n^2)$ worst case .
