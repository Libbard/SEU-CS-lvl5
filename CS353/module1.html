The Core Definition

An Algorithm is not just code. It is a sequence of clear instructions for solving a problem to acquire a required output for any legitimate input in a finite amount of time.

Think of it as a recipe: The ingredients are the input, the cooking steps are the algorithm, and the delicious meal is the output.

Characteristics of an Algorithm

Input

Zero or more quantities externally supplied.

Output

At least one quantity produced.

Definiteness

Instructions must be clear & unambiguous.

Finiteness

Must terminate after a finite number of steps.

Efficiency

Instructions must be basic and run quickly.

Specification Methods

Natural Language

Simple English. Drawback: Often ambiguous and verbose.

Pseudocode

Preferred

Mix of English and code structures. Implementation independent but precise.

Flowchart

Graphical representation. Drawback: Hard to modify and space-consuming for complex logic.

Case Study: Euclid's GCD

Pseudocode
ALGORITHM Euclid_gcd(m, n)
// Computes gcd(m, n) via Euclid's Method
// Input: Two non-negative integers

while n ≠ 0 do
r ← m mod n
m ← n
n ← r
return m

Logic: If $n=0$, the GCD is $m$. Otherwise, replace $m$ with $n$ and $n$ with the remainder of $m/n$.

The Problem Landscape

Sorting

Rearranging items in ascending/descending order. (e.g., QuickSort).

Searching

Finding a specific value (search key) in a dataset. (e.g., Binary Search).

String Processing

Handling text data, vital for Bioinformatics (DNA sequences) and search engines.

Graph Problems

Modeling connections (cities, networks). Examples: Shortest Path, Traveling Salesman.

Combinatorial

Finding permutations or subsets satisfying constraints. Often the hardest problems.

Geometric

Dealing with points, lines, polygons. Used in Computer Graphics and Robotics.

The Exam Vault

Professor's Secrets & Trap Avoidance

TRAP: Efficiency vs. Correctness

A super-fast algorithm (High Efficiency) is worthless if it gives the wrong answer (Zero Correctness). Correctness is the prerequisite; Efficiency is the goal. Never optimize before proving correctness.

TRAP: Algorithm vs. Program

An operating system is a Program (it runs indefinitely/infinite loop). An Algorithm MUST terminate (Finiteness). If asked "Is Windows an algorithm?", the answer is strictly No.

SECRET: Why Pseudocode?

Professors prefer pseudocode because it ignores syntax errors (semicolons, types) and focuses purely on logic. In exams, never write C++/Java syntax unless explicitly asked. Stick to standard pseudocode (`←` for assignment).

KEY CONCEPT: "Legitimate Input"

If an algorithm fails on $n = -1$ but the input was defined as "Positive Integers", the algorithm is still correct. Correctness is only judged against the defined valid range of inputs.
