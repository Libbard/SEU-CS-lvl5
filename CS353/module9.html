Hashing: The $O(1)$ Dream

The Dictionary Problem

We need to implement a set with three operations: Find, Insert, and Delete. Balanced Trees do this in $O(\log n)$. Hashing aims for $O(1)$ on average by trading space.

The Hash Function $h(K)$

Maps a key $K$ (large universe) to a small table index $[0, m-1]$.

$h(K) = K \mod m$

Ideally, $m$ should be a Prime Number to minimize patterns.

Handling Collisions

A Collision occurs when $h(K_1) = h(K_2)$. Since the table size $m < n$ (universe), collisions are inevitable.

1. Open Hashing

Separate Chaining

Keys are stored in Linked Lists attached to the table cells.

  • Logic: If collision, append node to the list.
  • Load Factor ($\alpha$): Can be $> 1$.
  • Search: $1 + \alpha/2$ (average).

2. Closed Hashing

Open Addressing

Keys are stored inside the table itself.

  • Linear Probing: If occupied, check $i+1, i+2...$
  • Load Factor ($\alpha$): Must be $\le 1$.
  • Clustering: Keys tend to clump together, slowing performance.

B-Trees

Why B-Trees?

Standard BSTs and AVL trees are great in RAM. But when data is too large (Databases, File Systems), it lives on Disk. Disk access is 10,000x slower than RAM. B-Trees minimize disk accesses (height) by expanding the node width.

Properties of a B-Tree of Order $m$

1. Balance

Perfectly balanced. All leaves are at the same depth.

2. Node Capacity

Every node (except root) has between $\lceil m/2 \rceil$ and $m$ children.

3. Keys

A node with $k$ children contains $k-1$ keys.

4. Growth

Grows upwards. When a node overflows, it splits and pushes a key to the parent.

The Exam Vault

Professor's Secrets & Trap Avoidance

TRAP: The Naming Confusion

This is the most common mistake:
Open Hashing = Separate Chaining (Linked Lists outside).
Open Addressing = Closed Hashing (Everything inside).
Memorize this opposition. "Open Addressing" means the address is open to other keys, but it is a "Closed Hashing" system.

TRAP: Hashing Worst Case

"Is Hashing always $O(1)$?"
NO! That is the average case. In the worst case (all keys collide to the same index), it degrades to $O(n)$ (searching a linked list). Never promise $O(1)$ without saying "average".

SECRET: Why Primes?

Why do we choose table size $m$ to be Prime?
If keys have a pattern (e.g., 10, 20, 30) and $m$ is 10, they all collide at index 0. A Prime number $m$ breaks up arithmetic patterns in the input keys, distributing them more evenly.

KEY CONCEPT: B+ Trees

The PDF mentions B+ Trees in the summary. The key difference from B-Trees: in B+ Trees, all data is stored in the leaves. Internal nodes only contain keys for navigation. This allows for faster sequential access (linked leaves).
