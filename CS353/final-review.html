Transform & Space-Time (Mod 7-9)

Heaps & Heapsort

Heap: An array viewed as a nearly complete binary tree.

  • Structure: Filled left-to-right.
  • Order: Parent $\ge$ Children (Max-Heap).
  • Construction: Bottom-up heapify takes $O(n)$.
  • Sort: Swap root/last, heapify. $O(n \log n)$.

Input Enhancement

preprocess input to gain speed.

  • Distribution Counting: $O(n+k)$ sort for small range $k$.
  • Horspool: String matching. Shift table based on last character of pattern. Avg $O(n)$.

Hashing & B-Trees

Hashing ($O(1)$ avg) Open (Chaining) vs Closed (Open Addressing).
B-Trees Balanced trees for Disk Storage. Nodes have multiple keys to minimize height (disk seeks).

Algorithm Design Paradigms

Dynamic Programming

Solves overlapping subproblems once and stores the result (Memoization/Tabulation).

Problem Logic Complexity
Knapsack 0/1 Max(Exclude, Include) $O(nW)$
Warshall Transitive Closure (OR/AND) $O(n^3)$
Floyd All-Pairs Shortest Path $O(n^3)$

Greedy Technique

Makes the locally optimal choice at each step. Fast, but only works for specific problems (Matroids).

Prim's Algorithm

Grow 1 tree. Use Priority Queue. Good for Dense graphs.

Kruskal's Algorithm

Merge forests. Use Union-Find. Good for Sparse graphs.

Dijkstra

Shortest Path. Like Prim's but accumulates weight. No Negative Edges.

Huffman

Lossless Compression. Prefix-free codes. Bottom-up tree build.

The Limits of Computing

P

Class P

Solvable in Polynomial Time ($O(n^k)$).

NP

Class NP

Solution Verifiable in Polynomial Time. (Includes P).

NPC

NP-Complete

The hardest problems in NP. If one is solved in P, $P=NP$. (e.g., TSP, SAT).

How to Cope with NP-Hard?

1. Exact Solutions (Smart Brute Force)

Backtracking: DFS state-space tree. Prune non-promising nodes. (N-Queens).
Branch-and-Bound: Optimization. Use bounds to prune. (Knapsack/TSP).

2. Approximation Algorithms

Accept a sub-optimal answer for speed.
Nearest Neighbor (TSP): Greedy. Unbounded error.
Multifragment Heuristic: Sort edges, add if no cycle/degree<3.

The Mega Exam Vault (Finals Edition)

Professor's Secrets & Trap Avoidance

TRAP: Heapsort Stability

Heapsort is NOT stable. The operation of swapping the root with the last leaf destroys the relative order of equal elements. Do not use it if stability is required (Use MergeSort instead).

TRAP: Hashing "O(1)"

Never say "Hashing is O(1)" without adding "on average". In the worst case (all keys collide), it degrades to $O(n)$. This distinction is often a 5-point deduction in exams.

TRAP: NP Definition

NP does NOT mean "Not Polynomial". It stands for Nondeterministic Polynomial. It means a solution can be verified in polynomial time. P is a subset of NP.

SECRET: Prim vs Kruskal

When to use which?
Dense Graphs ($E \approx V^2$): Use Prim's (with Adjacency Matrix).
Sparse Graphs ($E \approx V$): Use Kruskal's (depends on edges).

SECRET: Knapsack Distinction

Fractional Knapsack: Solvable by Greedy (Value/Weight ratio).
0/1 Knapsack: Greedy Fails. Requires Dynamic Programming ($O(nW)$).

SECRET: Backtracking vs B&B

Both use state-space trees.
Backtracking: For finding *all* solutions or feasibility (N-Queens).
Branch-and-Bound: For *optimization* (Min/Max cost). Uses bounds to prune more aggressively.
