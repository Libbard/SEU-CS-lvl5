Core: Relational Model & Constraints

The mathematical foundation of modern databases. Relations, Tuples, Keys, and Integrity Constraints.

Relation Schema Tuples & Domains Superkey vs Candidate Key Referential Integrity Entity Integrity

Relational Terminology

Formal Term Informal (Common) Term Definition
Relation Table A set of tuples. (The whole table).
Tuple Row / Record An ordered set of values: $< v_1, v_2, ..., v_n >$.
Attribute Column Header / Field Role played by a domain in a relation.
Domain Data Type / Set of Values Set of atomic values (e.g., Integer, Date).
Relation State Populated Table The set of tuples at a given moment in time.

Formal Definitions

Relation State $r(R)$

Formally, a relation state $r(R)$ is a subset of the Cartesian Product of the domains of its attributes.

$r(R) \subseteq dom(A_1) \times dom(A_2) \times ... \times dom(A_n)$

Example: If $dom(A1)=\{0,1\}$ and $dom(A2)=\{a,b\}$, Cartesian Product has 4 tuples. A state might have only $\{<0,a>, <1,b>\}$.

Characteristics

  • Ordering: Tuples are unordered (it's a Set). Attributes are ordered in the schema.
  • Atomicity: Values are atomic (indivisible). No composite or multivalued attributes in a cell (1NF).
  • Nulls: Represents unknown or inapplicable values.

Integrity Constraints

1. Key Constraints

Superkey (SK) Any set of attributes that uniquely identifies a tuple. No duplicates allowed.
Candidate Key (K) A Minimal Superkey. If you remove any attribute, it loses uniqueness.
Primary Key (PK): One of the candidate keys chosen to identify tuples. Underlined in schema.

2. Entity Integrity Constraint

The Primary Key attributes of a relation CANNOT have Null values.
Why? Because PK is used to identify tuples. You cannot identify something with "Unknown".

3. Referential Integrity Constraint

Specifies a relationship between two relations. A tuple in referencing relation $R_1$ referencing $R_2$ must refer to an existing tuple in $R_2$.

Foreign Key (FK) Rule: Value of FK must be either:
  • An existing Primary Key value in the referenced relation.
  • Null (if allowed).

Operations & Violations

Basic operations: INSERT, DELETE, UPDATE. These can violate constraints.

INSERT Can violate:
- Domain (wrong type)
- Key (duplicate PK)
- Entity Integrity (Null PK)
- Referential Integrity (FK not found)
DELETE Can violate:
- Referential Integrity only.
(If you delete a parent referenced by children).
UPDATE Can violate:
- All constraints depending on what is updated (PK or FK or non-key).
Handling Violations (Options):
  • RESTRICT / REJECT: Stop the operation.
  • CASCADE: Propagate the update/delete (e.g., delete parent $\to$ delete children).
  • SET NULL: Set referencing FK to Null.

The Exam Vault

Professor's Secrets & Trap Avoidance

TRAP: Superkey vs Key

Is every Key a Superkey? YES.
Is every Superkey a Key? NO. Only minimal superkeys are Keys. If a Superkey has redundant attributes (e.g., {SSN, Name}), it is NOT a Candidate Key.

TRAP: Foreign Key Nulls

"Can a Foreign Key be NULL?"
YES (usually), unless it is part of the Primary Key of the referencing table.
"Can a Primary Key be NULL?"
NEVER (Entity Integrity).

SECRET: Self-Referencing

A Foreign Key can refer to the same table. This is called a recursive relationship (e.g., Employee table with `Supervisor_SSN` referencing `SSN` in the same table).

KEY CONCEPT: Delete Rules

If you delete a parent record (referenced by others), the DBMS blocks it by default (RESTRICT). If you want it to automatically delete children, you must define ON DELETE CASCADE in the schema.
