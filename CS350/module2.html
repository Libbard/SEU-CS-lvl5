Data Models

A Data Model is a set of concepts to describe the structure of a database, operations for manipulating data, and constraints.

1. Conceptual

High-level, Semantic. Close to how users perceive data.
Example: Entity-Relationship Model.

2. Physical

Low-level, Internal. Describes how data is stored in the computer (bits, tracks).
Example: Record formats, ordering.

3. Implementation

Representational. Falls between the two. Used by commercial DBMSs.
Example: Relational Data Model.

Schema vs. State

Database Schema (Intension)

The description of the database. Includes structure, types, and constraints. Changes very infrequently.

Database State (Extension)

The actual data stored at a particular moment. Changes every time the database is updated (Snapshot).

Schema = Blueprint
State = The House content

External Level Describes part of the database for specific user groups (Views).
Conceptual Level Describes the structure of the WHOLE database for the community of users.
Internal Level Describes physical storage structures and access paths.

Logical Data Independence

Capacity to change the Conceptual Schema without changing External Schemas or Application Programs.

Physical Data Independence

Capacity to change the Internal Schema without changing the Conceptual Schema (e.g., creating a new index to improve performance).

Languages & Interfaces

DDL (Data Definition Language)

  • Used by DBA and designers.
  • Specifies the conceptual schema.
  • Examples: `CREATE TABLE`, `ALTER`.

DML (Data Manipulation Language)

  • Used for retrieval, insertion, deletion, and updates.
  • High-Level (Declarative): "What" to get (SQL).
  • Low-Level (Procedural): "How" to get it (Record-at-a-time).

The Exam Vault

Professor's Secrets & Trap Avoidance

TRAP: Logical vs Physical Independence

Physical Independence is changing the internal schema (e.g., adding an index) without breaking the conceptual schema.
Logical Independence is changing the conceptual schema (e.g., adding a column) without breaking external views/apps. Hint: Logical is harder to achieve.

TRAP: Schema vs State

If the question asks "Which of these changes frequently?", the answer is State (Extension). The Schema (Intension) changes rarely.

SECRET: 3-Schema Purpose

The main goal of the Three-Schema Architecture is Data Independence (Insulation between programs and data). It allows you to change the "plumbing" without rebuilding the house.

KEY CONCEPT: DDL vs DML

DDL = Definition (Structure, Tables, Indexes).
DML = Manipulation (Select, Insert, Update, Delete). Remember: DDL builds the bucket; DML fills it with water.
