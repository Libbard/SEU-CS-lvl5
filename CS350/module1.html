Basic Definitions

The Basics

  • Data: Known facts that have implicit meaning (e.g., Names, Numbers).
  • Database: A collection of related data. It represents a Miniworld (Universe of Discourse).
  • Meta-data: "Data about Data". The description of the database structure (types, constraints) stored in the DBMS catalog.

The System

  • DBMS: A software system to create, maintain, and control access to the database (e.g., Oracle, MySQL).
  • Database System: The combination of the Database + DBMS Software + Application Programs.

Simplified Database Environment

Why Use Databases?

Traditional file processing (saving data in text files) has many issues. The Database Approach solves them via four main characteristics:

1. Self-Describing Nature

The system contains not only the data but the structure of the data (Meta-data) in a catalog. This allows the DBMS to work with any database application.

2. Insulation (Data Abstraction)

Program-Data Independence: You can change the data structure (e.g., add a field) without rewriting the application code. The DBMS handles the mapping.

3. Multiple Views

Different users see different subsets of the data. A student sees grades; an admin sees transcripts.

4. Multi-user Transaction Processing

Allows concurrent access. The DBMS ensures Concurrency Control (e.g., two people booking the same seat) and OLTP (Online Transaction Processing).

Actors on the Scene

DBA (Administrator)

Controls access, coordinates use, acquires resources, and ensures efficiency. Accountable for security.

Database Designers

Identify data, choose structures/constraints, and communicate with users.

End Users

The people who query/update the data.

Categories:
  • Casual: Occasional access.
  • Naive (Parametric): Use "canned" transactions (e.g., Bank Tellers).
  • Sophisticated: Scientists/Analysts using tools.

When NOT to use a DBMS?

Using a DBMS incurs high costs (Investment, Hardware, Training, Overhead). Avoid it if:

  • The database and applications are simple, well-defined, and not expected to change.
  • Stringent real-time requirements (Overhead is too high).
  • Multiple user access is NOT required.

The Exam Vault

Professor's Secrets & Trap Avoidance

TRAP: Casual vs Naive Users

Naive (Parametric) users make up the largest group (e.g., Bank Tellers). They use standard, pre-programmed queries ("Canned Transactions").
Casual users access the DB occasionally and may need different info each time. Do not swap them!

TRAP: Program-Data Independence

In traditional file processing, if you change the data format (e.g., change zip code from 5 to 9 digits), you must rewrite every program that uses it. In a DBMS, you change the structure in the catalog (Meta-data) only. This is "Independence".

SECRET: Meta-data

If an exam question asks "What makes a database system self-describing?", the answer is Meta-data (stored in the Catalog). It describes the structure, types, and constraints.

KEY CONCEPT: The Goal

The ultimate goal of the database approach is to control (not necessarily eliminate) Redundancy. Controlled redundancy improves performance; uncontrolled redundancy leads to Inconsistency.
