Basic SQL: Manipulation (DML)

Retrieving, inserting, updating, and deleting data. Mastering the SELECT-FROM-WHERE block.

The SELECT Statement

The core of SQL retrieval. The basic form is mapping conceptual operations (Projection, Selection, Cartesian Product) into a simple syntax.

SELECT <attribute_list> FROM <table_list> WHERE <condition> ORDER BY <sort_list>;
SELECT (Projection) Lists the columns to be retrieved. Use `*` for all columns.
FROM (Join Source) Lists the tables involved. If >1 table, it implies a Cartesian Product.
WHERE (Selection) Filters the rows based on a boolean condition.

Example: Simple Retrieval

Retrieve birthdate and address of 'John B. Smith'.

SELECT Bdate, Address FROM EMPLOYEE WHERE Fname='John' AND Minit='B' AND Lname='Smith';

Pattern Matching & Sorting

Pattern Matching (LIKE)

Used for string comparison.
% = Zero or more characters.
_ = Exactly one character.

SELECT Fname, Lname FROM EMPLOYEE WHERE Address LIKE '%Houston, TX%';

Sorting (ORDER BY)

Sorts the result set. Default is ASC (Ascending). Use DESC for descending.


SELECT * FROM EMPLOYEE ORDER BY Dno ASC, Salary DESC;

Modification Statements

INSERT

Adds new tuple(s) to a table.

INSERT INTO EMPLOYEE (Fname, Lname, Ssn, Dno) VALUES ('Richard', 'Marini', '653298653', 4);

DELETE

Removes tuple(s) from a table based on a condition.

DELETE FROM EMPLOYEE WHERE Lname = 'Brown';

*Warning: Omitting WHERE deletes ALL rows.

UPDATE

Modifies attribute values of existing tuples.

UPDATE PROJECT SET PLOCATION = 'Bellaire', DNUM = 5 WHERE PNUMBER = 10;

Aliases & Implicit Joins

When querying multiple tables, we use the `WHERE` clause to specify the join condition (Foreign Key = Primary Key).

SELECT E.Fname, E.Lname, S.Fname, S.Lname FROM EMPLOYEE AS E, EMPLOYEE AS S WHERE E.Super_ssn = S.Ssn;
Self-Join Concept: In the example above, we join `EMPLOYEE` to itself to find Supervisors. We MUST use Aliases (E, S) to distinguish the two roles of the same table.

The Exam Vault

Professor's Secrets & Trap Avoidance

TRAP: Missing Join Condition

If you list 2 tables in `FROM` but forget the `WHERE` condition linking them, you get a Cartesian Product (Every row in Table A combined with Every row in Table B).
Result: Massive, incorrect output.

TRAP: Quote Confusion

Strings and Dates must be enclosed in single quotes ('Value'). Numbers must NOT be quoted (10, 50.5).
Example: `WHERE Salary > '30000'` might work in some SQL dialects but is conceptually wrong.

SECRET: The `*` Wildcard

`SELECT *` retrieves ALL columns. It is useful for quick checks but bad for production code (performance waste + code breaks if schema changes). In exams, `SELECT *` is acceptable unless asked for specific attributes.

KEY CONCEPT: Distinct

SQL `SELECT` creates a Bag (Multiset), allowing duplicates (e.g., listing all employee salaries might show '30000' twice). To get a Set (unique values), use `SELECT DISTINCT Salary`.
