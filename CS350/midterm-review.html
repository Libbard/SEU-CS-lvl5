Covering Modules 1-6

01. Foundations

Definitions

Core Concepts

  • Database (DB): Collection of related data representing a Miniworld.
  • DBMS: Software to define, construct, and manipulate the DB.
  • Meta-data: "Data about Data" (Structure, Constraints). Stored in the Catalog.

Key Advantages

Program-Data Independence: Changing data structure (e.g., adding a field) does NOT require rewriting applications. The DBMS handles the mapping.

02. Architecture

3-Schema

The Three Schemas

  • 1. Internal: Physical storage (Bits, Indices).
  • 2. Conceptual: Structure (Entities, Relationships). Hides storage details.
  • 3. External: User Views (Subsets of data).

Data Independence

Logical Change Conceptual w/o breaking External views.
Physical Change Internal (Optimization) w/o breaking Conceptual.

03. Relational Model

Tables & Constraints

Keys

  • Superkey: Unique identifier (can be redundant).
  • Candidate Key: Minimal Superkey.
  • Primary Key (PK): Chosen Candidate Key. Cannot be NULL.

Integrity Constraints

  • Entity Integrity: PK $\neq$ NULL.
  • Referential Integrity: Foreign Key (FK) must match an existing PK in the referenced table OR be NULL.

04. ER Modeling

Concepts

Attributes

Simple Composite (Address) Multi-valued (Color) { } Derived (Age)

Weak Entity

Has no Key. Identified by an Owner Entity via an Identifying Relationship.
Example: Dependent relies on Employee.

05. EER Inheritance

Super/Subclass

Specialization vs Generalization

  • Specialization (Top-Down): Breaking Entity into subgroups (Employee $\to$ Secretary, Engineer).
  • Generalization (Bottom-Up): Combining entities into a superclass (Car, Truck $\to$ Vehicle).

Inheritance

Subclasses inherit ALL attributes and relationships of the Superclass.

06. Mapping & Constraints

Logical Design

Constraint Types

Disjoint (d): Overlap NOT allowed.
Overlap (o): Entity can be in multiple subclasses.
Total (Double): Every Super must be a Sub.
Partial (Single): Super can exist alone.
Union Type (Category)

A subclass with multiple superclasses representing different entity types. Relation is OR.
(e.g., Owner is Person OR Bank OR Company).

The 7-Step Mapping Algorithm

Step 1: Strong Create table. Simple attributes become columns.
Step 2: Weak Create table. Add Owner PK as FK.
PK = {OwnerPK + PartialKey}.
Step 3: 1:1 Add PK of one side as FK to the other. Prefer Total Participation side.
Step 4: 1:N Add PK of "1-side" as FK to "N-side". (Parent ID goes to Child).
Step 5: M:N Create Associative Table. Include PKs of both sides as FKs. PK = {FK1, FK2}.
Step 6: Multi-Val Create new table. PK = {ParentID, Value}.
Step 7: N-ary Create new table with FKs from all participating entities.

The Midterm Mega Vault

All Secrets, Traps, and Tricks (Mod 1-6)

TRAP: Schema vs State

Schema (Intension): The blueprint. Changes rarely.
State (Extension): The data content. Changes frequently. Don't confuse them!

TRAP: 1:N Mapping

Never put the Foreign Key on the "1-side". It violates 1NF (atomic values).
Always put the FK on the N-side (the child).

TRAP: Weak Entity PK

A Weak Entity does NOT have a Primary Key of its own. It has a Partial Key. Its PK in the database is (Owner PK + Partial Key).

SECRET: Meta-Data

What makes a DBMS "Self-Describing"?
The existence of the System Catalog which stores the Meta-data (description of structure and constraints).

SECRET: Composite Attribute Mapping

When mapping a composite attribute (e.g., Address: City, Street), you do NOT create a separate table. You just flatten the components into columns (Address_City, Address_Street) in the main table.

SECRET: M:N Attributes

If a relationship has an attribute (e.g., "Hours Worked"), and the relationship is M:N, that attribute belongs to the Associative Entity (the middle table), not the Employee or Project tables.
