The Core Problem

Race Condition

A situation where several processes access and manipulate the same data concurrently, and the outcome depends on the particular order in which the access takes place.

// Example: Counter++ vs Counter--
Process A (count++)
1. reg1 = count
2. reg1 = reg1 + 1
3. count = reg1
Process B (count--)
1. reg2 = count
2. reg2 = reg2 - 1
3. count = reg2

If these instructions interleave (e.g., A1, B1, A2, B2...), the final value of count will be wrong.

The Critical Section (CS) Problem

A segment of code where the process accesses shared resources.

do { entry section CRITICAL SECTION exit section REMAINDER SECTION } while (TRUE);
The 3 Requirements for a Solution:
  1. Mutual Exclusion: If Process P is in CS, no other process can be in CS.
  2. Progress: If no one is in CS, and someone wants to enter, the selection cannot be postponed indefinitely.
  3. Bounded Waiting: There is a limit on how many times others can enter CS before a specific process is granted access (No starvation).

Solutions

Peterson's Solution (Software)

A classic software-based solution for 2 processes. Uses two variables: `turn` and `flag`.

flag[i] = true; turn = j; while (flag[j] && turn == j); // Busy Wait /* CRITICAL SECTION */ flag[i] = false;

Note: May not work on modern architectures due to instruction reordering.

Hardware Support

Modern systems provide special Atomic Instructions (Non-interruptible).

test_and_set() Reads a boolean value and sets it to TRUE atomically.
compare_and_swap() Compares content of memory with expected value; if equal, swaps it.

OS Tools

Mutex Locks

Short for MUTual EXclusion. The simplest tool.
A process must `acquire()` the lock before entering CS and `release()` it after.

acquire() { while (!available); // Busy wait available = false; } release() { available = true; }

Often called "Spinlocks" because of busy waiting.

Semaphores

More robust integer variable `S` accessed only via `wait()` (P) and `signal()` (V).

  • Counting Semaphore: Integer value unrestricted. Used for resource counting.
  • Binary Semaphore: 0 or 1. Equivalent to Mutex.
Avoiding Busy Wait:
Instead of spinning, a process can block itself and be placed in a waiting queue. `signal()` wakes it up.

Classic Synchronization Problems

1

Bounded-Buffer Problem

Producer generates data, Consumer eats it. Must synchronize access to the buffer (Full/Empty slots).

2

Readers-Writers Problem

Many readers can read simultaneously. Only one writer can write at a time (exclusive access).

3

Dining-Philosophers Problem

5 philosophers, 5 chopsticks. Need 2 to eat. How to prevent deadlock where everyone holds 1 stick?

Professor's Secrets & Trap Avoidance

TRAP: Spinlock Usage

"When is a Spinlock (Busy Wait) actually good?"
Answer: In Multiprocessor systems when the lock is held for a very short time. It avoids the expensive Context Switch required to put a process to sleep.

TRAP: Deadlock vs Starvation

Deadlock: Two or more processes are waiting indefinitely for an event that can only be caused by one of the waiting processes. (Everyone stuck).
Starvation: Indefinite blocking. A process waits forever but the system isn't frozen (others are proceeding).

SECRET: Semaphore Implementation

Semaphores themselves must be atomic. How do we ensure `wait()` and `signal()` don't have race conditions?
We implement them using ... Critical Sections (Spinlocks/Interrupt disabling) inside the Kernel! It's recursion all the way down.

KEY CONCEPT: Atomic Variable

Provides atomic updates on basic data types (integers, booleans) without explicit locks. Often used for counters.
Implemented via hardware CAS (Compare-And-Swap).
