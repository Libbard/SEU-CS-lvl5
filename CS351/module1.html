What is an Operating System?

An OS is a program that acts as an Intermediary between the user and the hardware.

Main Goals

  • Convenience: Makes the computer easier to use (Abstraction). Turns "ugly hardware" into beautiful interfaces.
  • Efficiency: Manages resources (CPU, Memory, Disk) optimally.
  • Protection: Ensures security and reliability.

Key Definitions

  • Kernel: The one program running at all times. The core of the OS.
  • System Programs: Ships with the OS but not part of the kernel (e.g., File Manager).
  • Application Programs: User software (e.g., Chrome, Word). Not part of the OS.

System Architecture

The Bootstrap Program

The first code executed on power-up.

  • Stored in ROM or EEPROM (Firmware).
  • Initializes all hardware (CPU, Memory, Controllers).
  • Loads the OS Kernel into memory and starts execution.

Interrupts

The mechanism for Hardware/Software to signal the CPU.

  • Hardware Interrupt: Signal from device (e.g., Key press, Disk ready).
  • Software Interrupt (Trap/Exception): Signal from software (e.g., Error, System Call request).
  • Handling: CPU stops, saves state, jumps to Interrupt Service Routine (ISR) via the Interrupt Vector.

Architecture Types

Multiprocessor Systems (Parallel)

Systems with 2 or more processors in close communication, sharing the computer bus, clock, memory, and peripherals.

Asymmetric (Master-Slave) One Master CPU controls the system. Others look to the master for instruction.
Symmetric (SMP) Most common. Each processor performs all tasks. All are peers.

Clustered Systems

Multiple individual systems (nodes) gathered together. Usually share storage via a Storage Area Network (SAN).
High Availability: If one node fails, another takes over.

OS Operations

Dual-Mode Operation

Critical Concept

To protect the OS from user errors, hardware provides two modes:

User Mode (Bit 1)

Restricted access. Cannot execute privileged instructions (e.g., halting CPU, accessing I/O directly).

Kernel Mode (Bit 0)

Full access. Executes privileged instructions. Entered via System Calls or Interrupts.

System Calls

The programming interface to the services provided by the OS. Typically written in C/C++.

user@os:~$ ./app
// App needs to read a file...
1. User App calls open() -> Switches to Kernel Mode
2. OS executes sys_open() -> Hardware Access
3. OS returns file handle -> Switches back to User Mode

The Exam Vault

Professor's Secrets & Trap Avoidance

TRAP: System Call vs API

APIs (like `printf()` in C) are library functions running in User Mode.
System Calls (like `write()`) are the actual OS entry points running in Kernel Mode. Most APIs eventually invoke System Calls, but they are not the same thing.

TRAP: Mode Switching

The switch from User to Kernel mode happens via a Trap (Software Interrupt). It is hardware-triggered by a specific instruction. It is NOT just a simple function call jump.

SECRET: The Timer

How does the OS prevent an infinite loop in a user program from freezing the whole system?
The Timer Interrupt. The hardware timer periodically interrupts the CPU, giving control back to the OS scheduler. This ensures the OS always regains control.

KEY CONCEPT: Virtualization

Emulation runs code for a different CPU type (slow).
Virtualization runs code for the SAME CPU type but isolates it (fast). The Hypervisor (VMM) sits between hardware and OS to manage VMs.
