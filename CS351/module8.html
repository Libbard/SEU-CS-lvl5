Illusion of Space: Virtual Memory

Running programs larger than physical memory. Demand Paging, Page Faults, Thrashing, and Replacement Algorithms.

Demand Paging Page Fault Copy-on-Write (COW) FIFO/LRU/Optimal Thrashing

Why Virtual Memory?

Concept: Separation of user logical memory from physical memory.
Only part of the program needs to be in memory for execution.

Benefits
  • Logical address space can be much larger than physical address space ($2^{64}$ vs 16GB RAM).
  • More programs can run simultaneously (Higher CPU utilization).
  • Less I/O needed to load or swap processes.
Implementation
  • Demand Paging: Load pages only when needed.
  • Demand Segmentation: (Less common).

Demand Paging

The Lazy Swapper

Never brings a page into memory until it is required.
Valid-Invalid Bit: With each page table entry, a bit is associated (v = in memory, i = not in memory).

Page Fault Handling Steps:
  1. Access to a page marked 'i' $\to$ Trap to OS (Page Fault).
  2. OS checks internal table: Invalid reference $\to$ Abort. Just not in memory $\to$ Continue.
  3. Find a free frame in physical memory.
  4. Schedule disk operation to read page into frame.
  5. Reset page table (v = 1).
  6. Restart the instruction that caused the fault.

Performance of Demand Paging

Effective Access Time (EAT) depends heavily on the Page Fault Rate ($p$).

EAT = (1 - p) * ma + p * (Page Fault Time)

ma = memory access time (~10-200ns).
Page Fault Time = service fault + read page + restart (~8ms).
Even a small $p$ enables drastic slowdown.

Page Replacement

What if there are no free frames? We must find a victim frame, write it to disk (if modified), and replace it.
Goal: Minimize page-fault rate.

FIFO (First-In, First-Out)

Replace the oldest page. Simple queue implementation.

Belady's Anomaly: Adding more frames can cause more page faults!

Optimal Algorithm

Replace the page that will not be used for the longest period of time.
Impossible to implement (requires future knowledge). Used as a benchmark.

LRU (Least Recently Used)

Replace the page that has not been used for the longest period of time. (Approximation of Optimal).
Implementation: Counters or Stack. Good performance, no Belady's Anomaly.

Allocation & Thrashing

Frame Allocation

  • Fixed: Equal allocation or Proportional to size.
  • Global Replacement: Process can steal frames from others. (Good throughput, variable execution time).
  • Local Replacement: Must steal from own set. (Consistent perf, potentially lower throughput).

Thrashing

A process is busy swapping pages in and out (Page Fault Rate > Service Rate).
CPU Utilization drops to near zero.

Cause: $\Sigma$ Size of Locality > Total Memory Size.
Solution: Working Set Model (Monitor active pages per process and suspend processes if memory is insufficient).

The Exam Vault

Professor's Secrets & Trap Avoidance

TRAP: Modify Bit

"Why use a Modify (Dirty) bit?"
If the victim page has NOT been modified (Dirty bit = 0), we do NOT need to write it back to disk (it's already there). This saves 50% of the I/O time on replacement.

TRAP: Belady's Anomaly

Belady's Anomaly (more frames = more faults) happens with FIFO. It does NOT happen with LRU or Optimal (Stack Algorithms).

SECRET: Copy-on-Write (COW)

`fork()` creates a child process. Instead of copying ALL parent pages (slow), COW allows parent and child to share the same pages initially.
Only if one writes to a page is a copy created. This makes process creation extremely fast.

KEY CONCEPT: Working Set

To prevent thrashing, the OS must ensure the process has enough frames to cover its current Locality (set of pages actively used together).
If $\Sigma$ Working Sets > Available Frames $\to$ Swap out a process.
