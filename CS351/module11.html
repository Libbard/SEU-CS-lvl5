File Concepts

A file is a named collection of related information recorded on secondary storage.
Abstraction: The OS maps files to physical devices (blocks), hiding complexity.

Attributes (Metadata)
  • Name (Human readable)
  • Identifier (Unique tag, Inode number)
  • Type, Location, Size
  • Protection (Access control)
  • Time/Date (Creation, Modification)
Operations
  • Create, Write, Read, Reposition (Seek)
  • Delete, Truncate
  • Open ($F_i$): move attributes to memory.
  • Close ($F_i$): flush buffers to disk.

Directory Structure

Evolution of Directories

  • Single-Level: All files in one directory. Name collisions, hard to manage.
  • Two-Level: Master File Directory + User File Directory. Solves name collision between users.
  • Tree-Structured: Arbitrary depth. Standard today. Efficient searching and grouping.
  • Acyclic Graph: Allows shared subdirectories/files (Aliasing/Links). Danger of dangling pointers.

Mounting

A file system must be Mounted before it can be accessed.
The OS is given the name of the device and the Mount Point (location within the existing directory structure where the FS attaches).

Allocation Methods

How do we allocate disk blocks to files?

Contiguous

Each file occupies a set of contiguous blocks.
Simple (Start, Length).
Excellent read performance.

Problems: External fragmentation, hard to grow files.

Linked

Each file is a linked list of blocks.
No external fragmentation.
Easy to grow.

Problems: Slow random access (must traverse list), reliability (lost pointer = lost file).

Indexed

Bring all pointers together into an Index Block.
Supports direct access without external fragmentation.
Standard in modern systems (e.g., Inodes).

Free Space Management

Bit Vector (Bit Map)

1 bit per block. (1 = free, 0 = occupied).
Easy to find first free block.
Efficient if kept in memory.

Linked List

Link together all free blocks.
No waste of space (store pointer in free block itself).
Inefficient to traverse.

The Exam Vault

Professor's Secrets & Trap Avoidance

TRAP: Hard vs Soft Links

Hard Link: Another directory entry pointing to the same Inode. Deleting the original filename does NOT delete the file data (until link count = 0).
Soft (Symbolic) Link: A file containing the path to another file. If the original is deleted, the link becomes broken (dangling).

TRAP: VFS

Virtual File System (VFS): An abstraction layer. It allows different file systems (NTFS, FAT32, NFS) to coexist. The OS talks to VFS, VFS talks to specific FS drivers. It separates generic operations from implementation details.

SECRET: Buffer Cache

Modern OSs integrate the Virtual Memory system with the File System Buffer Cache. This is called Unified Buffer Cache. Memory-mapped I/O uses the same page cache as standard file I/O, preventing double caching (storing data twice in memory).

KEY CONCEPT: ZFS & Copy-on-Write

Advanced file systems like ZFS never overwrite blocks in place. They write new data to a new block and then update the pointer. This makes the file system consistent at all times (no corruption on power loss) and enables instant snapshots.
