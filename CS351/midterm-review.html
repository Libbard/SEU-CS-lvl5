Module 1: OS Services & Structure

Dual Mode Operation

Hardware protection against erratic users.

User Mode (Bit 1) Restricted. No I/O instructions. No HALT.
Kernel Mode (Bit 0) Privileged. Access to all hardware instructions.
Transition: User $\to$ Kernel via System Call (Trap). Kernel $\to$ User via Return from Trap.

System Calls

The API between User Programs and the OS.

// Example: Copy File read(src, buffer); -> Trap to Kernel write(dest, buffer); -> Trap to Kernel

Common APIs: POSIX (Linux/Unix), Win32 (Windows), Java API.
Note: `printf()` is a library call, which eventually calls `write()` (System Call).

Module 2: Processes & Threads

Process State Diagram

stateDiagram-v2 New --> Ready: Admitted Ready --> Running: Scheduler Dispatch Running --> Ready: Interrupt Running --> Waiting: I/O Wait Waiting --> Ready: I/O Complete Running --> Terminated: Exit

PCB (Process Control Block)

The "Soul" of the process.

  • PID: Unique ID.
  • Program Counter: Next instruction.
  • Registers: CPU state.
  • Memory Limits: Base/Limit.
  • Open Files: I/O list.
Context Switch: Saving PCB of old process and loading PCB of new one. Pure overhead!

Module 3: Scheduling

Turnaround Time
$T_{completion} - T_{arrival}$
Waiting Time
$Turnaround - Burst$
FCFS First-Come First-Served.
Problem: Convoy Effect (Short waits for Long).
Non-Preemptive.
SJF / SRTF Shortest Job First.
Benefit: Optimal Avg Wait Time.
Problem: Starvation, Predicting next burst.
Round Robin (RR) Time Quantum ($q$).
Fair. Good response time.
High context switch overhead if $q$ is small.
Priority Highest priority runs.
Problem: Starvation.
Solution: Aging.

Module 4: Synchronization Tools

Critical Section (CS) Requirements

  1. Mutual Exclusion: Only one process in CS at a time.
  2. Progress: If CS is empty, selection isn't postponed indefinitely.
  3. Bounded Waiting: Limit on times others enter CS before me (No starvation).

Semaphores (S)

wait(S) { while (S <= 0); S--; }
signal(S) { S++; }

Counting Semaphore: For resource pools.
Binary Semaphore: Same as Mutex (0 or 1).

Module 5: Classical Problems

1
Bounded Buffer

Producer/Consumer. Needs 3 semaphores: `mutex` (lock), `full` (item count), `empty` (space count).

2
Readers-Writers

Multiple Readers OK. Writer needs exclusive access. Problem: Writer Starvation.

3
Dining Philosophers

5 chairs, 5 sticks. Need 2 to eat. Deadlock if everyone takes Left stick at once.

Module 6: Deadlocks

The 4 Necessary Conditions

ALL must hold for deadlock to occur.

  • Mutual Exclusion
  • Hold and Wait
  • No Preemption
  • Circular Wait

Banker's Algorithm

Used for Deadlock Avoidance.

Need[i] = Max[i] - Allocation[i]

Check if system is in a Safe State (Is there a sequence where everyone can finish?).
If Request $\le$ Available, pretend to allocate and check Safety.

PROFESSOR'S SECRETS

The Mega Vault: Midterm Edition

Fork Logic

`fork()` returns 0 to Child, PID to Parent.
Child gets a copy of data, not shared memory.

User vs Kernel Threads

User threads are fast but if one blocks, the whole process blocks (Many-to-One). Kernel threads are slower (overhead) but independent (One-to-One).

Wait Time Formula

Do NOT just sum waiting periods. Always use:
$Wait = Turnaround - Burst$.
It reduces calculation errors.

Signal Order

In Bounded Buffer, order matters.
`wait(empty)` BEFORE `wait(mutex)`.
If swapped $\to$ Deadlock.

RAG Cycles

Cycle in RAG $\neq$ Deadlock (if multiple instances exist).
Cycle in RAG == Deadlock (if only 1 instance per resource).

Monitor Signal

Monitor `signal()` is not persistent. If no one is waiting, the signal is lost. Semaphore `signal()` increases counter (persistent).
