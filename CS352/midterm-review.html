Midterm Knowledge Compendium

A complete synthesis of Modules 1 through 6. This visual guide covers the Foundations, Planning, Analysis, and Process Modeling required for the Midterm Exam.

Modules 1-6 Covered

01. Foundations

SDLC & Agile

The SDLC Phases (Waterfall)

  • 1. Planning: Identify, analyze, prioritize needs.
  • 2. Analysis: Determine Requirements ("What").
  • 3. Design: Logical (Biz) & Physical (Tech) specs ("How").
  • 4. Implementation: Code, Test, Install, Support.
  • 5. Maintenance: Repair and improve (Repeats SDLC).

Agile Methodologies

eXtreme Programming (XP) Short cycles, Pair Programming, Automated Tests.
Scrum Sprints (2-4 weeks), Product Backlog, Daily Standup.

02. Project Mgmt

Planning & Scheduling

The 4 Phases

Initiation (Charter) $\to$ Planning (Baseline Plan, WBS) $\to$ Execution (Do work) $\to$ Closedown (Reviews).

Scheduling Tools

Gantt Charts Bars vs Time. Shows overlap/duration. Good for progress tracking.
Network Diagrams Nodes/Arrows. Shows dependencies. Essential for Critical Path.
KEY CONCEPT: Critical Path

The sequence of tasks with Zero Slack. It is the longest path through the network but determines the shortest time to finish.

03. Identification

Selection Strategy

Project Sources

  • Top-Down: Strategic, Upper Mgmt. Better integration, broader scope.
  • Bottom-Up: Tactical, User Depts. Faster, solves specific pain points.

Evaluation Criteria

Projects are selected based on Value Chain Analysis and Strategic Alignment.

Value Chain Resource Availability Potential ROI

04. Initiation

Feasibility

Six Types of Feasibility

  • Economic: ROI, NPV.
  • Technical: Risk/Skill.
  • Operational: Usage.
  • Schedule: Time.
  • Legal: Compliance.
  • Political: Stakeholders.

Baseline Project Plan (BPP)

The primary deliverable. It contains the best estimate of scope, benefits, costs, risks, and resource requirements.

05. Requirements

Gathering

Traditional Methods

  • Interviews: Open (Detail) vs Closed (Quantifiable).
  • Observation: "Informal" system. Risk: Hawthorne Effect.
  • Docs: "Formal" system procedures.

Modern Methods

  • JAD: Off-site, intense group workshop. Conflict resolution.
  • Prototyping: Iterative. Good when reqs are unclear.
  • BPR: Radical change. "Obliterate don't automate."

06. Process Modeling

DFD

DFD Symbols (Gane & Sarson)

Process: Rounded Rect (Verb).
Data Store: Open Rect (Noun).
Source/Sink: Square (External).
Flow: Arrow (Data in motion).

Logic Modeling

Decision Tables: Matrix of Conditions and Actions. Used to document complex logic inside a Process.

Essential Formulas & Rules

PERT Expected Time

$ET = \frac{o + 4r + p}{6}$

Weighted average of Optimistic (o), Realistic (r), and Pessimistic (p) times.

Slack Time

$Slack = T_L - T_E$

Latest Finish time minus Earliest Finish time. Critical Path has Zero Slack.

DFD Balancing Rule

Inputs(Parent) == Inputs(Child)
Outputs(Parent) == Outputs(Child)

Data cannot magically appear or disappear when decomposing a process.

The Midterm Mega Vault

All Secrets, Traps, and Tricks (Mod 1-6)

TRAP: Analysis vs Design

Analysis: Understanding the problem ("What"). Output: Requirements.
Design: Specifying the solution ("How"). Output: Blueprints.
Don't confuse "What the system does" with "How it is built".

TRAP: The Critical Path

It is the LONGEST path through the network diagram. However, it represents the SHORTEST possible time to complete the project. Shortening a non-critical task does NOT shorten the project.

TRAP: Illegal DFD Flows

Data Store $\to$ Data Store (Illegal).
External Entity $\to$ Data Store (Illegal).
External Entity $\to$ External Entity (Illegal).
ALL data must move through a PROCESS.

SECRET: Incremental Commitment

The project is not approved once and for all at the beginning. It is re-evaluated after EVERY phase (Planning, Analysis, Design). It can be cancelled at any point.

SECRET: JAD Locations

Joint Application Design (JAD) sessions MUST be held off-site. The isolation from daily tasks and phone calls is critical for the intense collaboration required.

SECRET: Context Diagram Rules

A Context Diagram (Level 0) has only ONE process symbol (labeled "0"). It shows the system boundary. It does NOT show Data Stores (unless they are external to the system).
