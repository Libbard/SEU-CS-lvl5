Process Modeling

Graphically representing the processes that capture, manipulate, store, and distribute data between a system and its environment.

The Core Tool: Data Flow Diagram (DFD)

DFD Mechanics

DFD Symbols (Gane & Sarson)

Data Store

Data at rest (File, DB table). [D1]

Process

Work/Action performed on data. [Verb Phrase]

Source/Sink (External Entity)

Origin/Destination of data outside the system.

Data Flow

Arrows depicting data movement.

Hierarchy of DFDs

  • Context Diagram (Level 0) Overview. Shows the system boundary, external entities, and major data flows. Only ONE process (The System). No data stores shown.
  • Level-0 Diagram Zooms in. Shows the system's major processes, data flows, and data stores.
  • Functional Decomposition Breaking down high-level processes into more detailed DFDs (Level-1, Level-2...).

The Exam Vault

Professor's Secrets & Trap Avoidance

TRAP: The Black Hole

In DFDs, a Process must have both inputs and outputs.
Black Hole: Inputs but NO outputs (Data disappears).
Miracle: Outputs but NO inputs (Data created from nothing). Both are errors!

TRAP: Data Store Rules

Data cannot move directly from one Data Store to another. It MUST go through a Process.
Similarly, data cannot move directly from an External Entity to a Data Store. It requires a Process to receive and store it.

SECRET: Context vs Level-0

Context Diagram: ONE process box (System 0). No Data Stores. Level-0: Multiple process boxes (1.0, 2.0...). Shows Data Stores. Don't mix them up!

KEY CONCEPT: Balancing

DFD Balancing: Inputs and outputs on a child diagram must match the inputs and outputs of the parent process on the higher-level diagram. If Process 1 has 2 inputs and 1 output, its Decomposition Diagram must essentially have those same net flows.
