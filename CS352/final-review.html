08. Conceptual Data

ERD & UML

Entity Relationships

M:N Problem: Many-to-Many relationships cannot be implemented directly in a relational DB. You must use an Associative Entity (Junction Table) to break it into two 1:M relationships.

UML Class Relationships

  • Aggregation (Hollow ◇): "Has-a". Weak bond. Parts survive if whole dies (e.g., Computer/Mouse).
  • Composition (Solid ◆): "Part-of". Strong bond. Parts die if whole dies (e.g., Building/Room).

09. DB Design

Normalization

Normalization Rules

  • 1NF: Atomic values. No lists/repeating groups.
  • 2NF: 1NF + No Partial Dependency. (Only relevant for Composite Keys).
  • 3NF: 2NF + No Transitive Dependency. (Non-key depends on Non-key).

13. Maintenance

Long Haul

Types of Maintenance

  • Corrective (70%): Fixing bugs.
  • Adaptive: OS/Environment changes.
  • Perfective: Enhancements/Performance.
  • Preventive: Future-proofing (Refactoring).

Key Facts

Maintenance is the Most Expensive phase (60-80% of TCO). It is a repeating SDLC process (Plan, Analyze, Design, Implement, Test).

Key Concepts Summary

The Final Exam Mega Vault

Secrets for Mod 7-13

TRAP: 2NF Requirement

"Does every table need 2NF checking?"
NO. If the Primary Key is a single attribute (not composite), the table is automatically in 2NF. You only check for Partial Dependencies if the PK has multiple fields.

TRAP: Fat vs Thin Client

Fat Client: Processing happens on the PC (Presentation + Logic). Hard to update.
Thin Client: Processing happens on the Server. PC is just UI. Easy to update.

TRAP: System vs User Doc

System Doc: Records design decisions (For Programmers).
User Doc: Records how to use it (For End Users). Do not confuse the target audience.

SECRET: The M:N Fix

You cannot implement M:N in a database. You MUST create an Associative Entity.
Example: Student $\leftrightarrow$ Course becomes Student $\leftarrow$ Registration $\rightarrow$ Course.

SECRET: Maintenance Reality

Maintenance is NOT just fixing bugs (Corrective). Most maintenance effort actually goes to Enhancements (Perfective) and Adaptation (Adaptive) to keep the system alive.

SECRET: XOR vs AND

In Activity Diagrams:
XOR (Diamond): "OR". Only 1 path.
AND (Bar): "AND". All paths parallel. Confusing these destroys the logic flow.
