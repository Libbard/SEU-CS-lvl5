The Implementation Phase

This is the second most expensive phase (after Maintenance). It involves many people: Analysts, Designers, Programmers, Technical Writers, and Testers.

Key Activities:
  • Coding (Programming)
  • Testing (Verification)
  • Installation (Deployment)
  • Documentation
  • Training & Support
Key Deliverables:
  • Code & Test Plans
  • User Manuals
  • Training Materials
  • Installed System

Software Application Testing

Static Testing (No Execution)

Code is reviewed without running it.

  • Inspection: Detecting errors (syntax).
  • Walkthrough: Detecting logic errors (peer review).
  • Desk Checking: Manual trace by programmer.

Dynamic Testing (Execution)

Code is run with test data.

  • Unit Testing: Single module.
  • Integration Testing: Modules working together.
  • System Testing: Whole system vs Requirements.

Installation Strategies

Direct Installation

Turn off old system, turn on new one immediately. "Cold Turkey".
High Risk. Low Cost.

Parallel Installation

Run both old and new systems simultaneously for a period.
Low Risk. High Cost (Double entry).

Single Location (Pilot)

Try it in one branch first. Learn, fix, then rollout.
Medium Risk. Limits damage.

Phased Installation

Install one module at a time (e.g., Accounts Payable, then Receivable).
Complex Coordination.

Documentation & Security

Documentation Types

  • System Documentation For maintenance programmers. Details design specs, internal code logic, and data structures.
  • User Documentation For end-users. Details how to use the system (Manuals, Help guides).

Security Issues

Data is a valuable asset. Threats include:

  • External: Hacking, Malware (48% of breaches).
  • Internal: Privilege misuse (28% of breaches).
  • Accidental: Human error.
Cost of Data Breach: ~$4.9M (Middle East)

The Exam Vault

Professor's Secrets & Trap Avoidance

TRAP: System vs User Documentation

System Doc: Tells you how the system is built (For Programmers). User Doc: Tells you how to use the system (For Users). Do not confuse the audience.

TRAP: Testing Order

You cannot do System Testing before Integration Testing. You cannot do Integration Testing before Unit Testing. It is a bottom-up verification process (Smallest pieces first).

SECRET: Alpha vs Beta

Alpha Testing: Done by users using simulated data (controlled environment). Beta Testing: Done by users using REAL data in their REAL environment (live).

KEY CONCEPT: The Cost of Errors

Finding a bug in the Implementation phase is 100x more expensive than finding it in the Analysis phase. This is why we spend so much time on Requirements gathering!
