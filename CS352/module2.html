The Project Manager

A Project Manager is a systems analyst with a diverse set of skills: management, leadership, technical, conflict management, and customer relationship management.

[cite_start]They are responsible for initiating, planning, executing, and closing down a project[cite: 8]. Their focus changes over the life of the project:

Early Phases Technique & Innovation
Later Phases Management & Control

The Project Management Process

1. Initiation

Start the Engine

  • Establish the Initiation Team.
  • Establish relationships with customers.
  • Establish the Project Initiation Plan.
    • [cite_start]
  • Outcome: Project Charter[cite: 13].

2. Planning

The Roadmap

  • Describe Scope, Alternatives, and Feasibility.
  • Divide project into manageable tasks (WBS).
  • Estimate resources and create a Preliminary Schedule (Gantt/PERT).
    • [cite_start]
  • Outcome: Baseline Project Plan[cite: 17].

3. Execution

Doing the Work

  • Execute the Baseline Project Plan.
  • Monitor progress against the Baseline Plan.
  • Manage changes to the Baseline Plan.
    • [cite_start]
  • Maintain the Project Workbook[cite: 19].

4. Closedown

Finalizing

  • Close down the project (terminate contracts).
  • Conduct post-project reviews.
  • Close the customer contract.

Scheduling Tools

Gantt Charts

  • Show task durations as bars.
  • Show time overlap.
  • Can show slack time.
  • Best for: Tracking progress and simple schedules.

Network Diagrams (PERT/CPM)

  • Show task dependencies (precedence).
  • Show parallelism.
  • Used to calculate the Critical Path.
  • Best for: Complex projects with many dependencies.

Estimating Task Duration

In PERT (Program Evaluation Review Technique), we use a weighted average of three estimates to calculate expected time ($ET$):

The Exam Vault

Professor's Secrets & Trap Avoidance

TRAP: The Critical Path

"Is the Critical Path the shortest path?"
NO. It is the longest path through the network. It dictates the shortest possible time to complete the project. If any task on the critical path is delayed, the whole project is delayed.

TRAP: Slack Time

Tasks on the Critical Path have Zero Slack. Slack is the amount of time a task can be delayed without delaying the project.
$Slack = T_L - T_E$ (Latest finish - Earliest finish).

SECRET: Baseline vs Actual

The Baseline Project Plan is what you planned at the start. The Actual is what really happened. A Project Manager's main job during Execution is monitoring the deviation between these two.

KEY CONCEPT: WBS

You cannot build a schedule (Gantt/PERT) without a Work Breakdown Structure (WBS) first. The WBS identifies *what* needs to be done (the tasks). The schedule decides *when* (the timing).
