Design: Distributed & Internet Systems

Moving from monolithic systems to distributed architectures. LANs, Client/Server, Cloud Computing, and SOA.

LAN vs WAN Client/Server Cloud Computing Middleware SOA

Designing LAN Systems

Local Area Networks (LANs) support workgroups. The design typically involves sharing resources (printers, databases) efficiently.

File Server Model

The client requests a file, and the entire file is sent to the client for processing.

  • High network traffic.
  • Client needs high processing power (Fat Client).
  • Data integrity issues (concurrent updates).

Client/Server Model

The client requests data, the server processes the request (e.g., SQL query) and sends back only the result.

  • Lower network traffic.
  • Processing is distributed.
  • Better data integrity (DBMS handles locking).

Advanced Architectures

Three-Tier Architecture

Separating the application logic from the data and the user interface.

1. Presentation Tier
(Client/Browser)
2. Application Tier
(Business Logic/Web Server)
3. Data Tier
(Database Server)

Cloud Computing

Provisioning computing resources (hardware, software) over the internet on-demand.

IaaS Infrastructure as a Service. (Hardware, Storage, Network). e.g., AWS EC2.
PaaS Platform as a Service. (OS, Runtime, Middleware). e.g., Google App Engine.
SaaS Software as a Service. (Applications). e.g., Salesforce, Gmail.

Designing Internet Systems

Standards

  • BPEL: Business Process Execution Language.
  • SOAP: Simple Object Access Protocol (XML based).
  • XML: Extensible Markup Language (Data structure).

Key Issues

  • Security: Balancing ease of use with protection.
  • Performance: Variable connection speeds.
  • Integration: Combining legacy data with new web apps.

Content Management Systems (CMS)

Software that collects, organizes, and publishes website content. It separates the content (text/images stored in DB) from the presentation (templates). This allows non-technical users to update sites without knowing HTML.

Service-Oriented Architecture (SOA)

SOA (Service-Oriented Architecture)

Business processes broken down into individual Services.

  • Reusability: A "Check Credit" service can be used by Sales, Finance, and Web Store.
  • Interoperability: Services communicate via standard protocols (like XML/SOAP), regardless of the language they were written in.
  • Componentization: Build systems like Lego blocks.

The Exam Vault

Professor's Secrets & Trap Avoidance

TRAP: File Server vs Client/Server

File Server: Sends the *whole file* to the client. Processing happens on the Client. (Bad for big data). Client/Server: Server processes the query and sends *only results*. Processing happens on the Server. (Good for big data).

TRAP: Fat vs Thin Client

Fat Client: PC does most of the processing (Presentation + Logic). Server just holds data. Thin Client: PC only does Presentation (UI). Server does Logic + Data. (Easier to update software).

SECRET: Middleware

Middleware is the "glue" that allows disparate systems to talk. It sits between the OS and the Application.
Example: ODBC/JDBC allows a Java program to talk to an Oracle Database without knowing Oracle-specific commands.

KEY CONCEPT: SOA Benefits

Why SOA? It decouples systems. If you change the "Credit Check" code, you don't break the Sales System, as long as the Service Interface (Input/Output) stays the same.
