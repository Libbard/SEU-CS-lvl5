Maintenance: Managing the Long Haul

The longest and most expensive phase of the SDLC. Fixing bugs, adding features, and keeping the lights on.

Corrective Maintenance Adaptive Maintenance Perfective Maintenance Preventive Maintenance MTBF

The Process

Maintenance typically begins immediately after system installation. It is an iterative process similar to the SDLC itself (Request $\to$ Analyze $\to$ Design $\to$ Implement).


1. Maintenance Request

2. Transform to Change Request

3. Design & Implement

4. Release New Version

Types of Maintenance

1. Corrective

70% of effort (Historically)

Repairing defects (bugs). Fixing things that are broken or causing errors.

2. Adaptive

Changing Environment

Modifying the system to adapt to changes in the environment (e.g., New OS version, New Tax Laws).

3. Perfective

Value Add

Evolving the system to add new features or improve performance. Makes the system "better".

4. Preventive

Future Proof

Changes made to avoid future problems (e.g., Refactoring code, optimizing DB index before it gets slow).

Managing Maintenance

What Drives Cost?

  • Latent Defects: Unknown bugs.
  • Number of Customers: More users = more requests.
  • Documentation Quality: Poor docs = slower fixes.
  • Personnel: Staff turnover kills knowledge.

Key Metrics

MTBF (Mean Time Between Failures)

Measure of reliability. Higher is better.

MTTR (Mean Time To Repair)

Measure of maintainability. Lower is better.

Website Maintenance

Websites require 24/7 availability ("The store never closes"). Maintenance is often continuous.

Professor's Secrets & Trap Avoidance

TRAP: Maintenance Cost

"Is Implementation the most expensive phase?"
NO. Maintenance is. It accounts for 60-80% of the total lifecycle cost of a system.

TRAP: Corrective vs Adaptive

Corrective: Fixing a bug (e.g., "The calculation is wrong"). Adaptive: Reacting to environment (e.g., "The government changed the tax rate to 15%"). The system wasn't "broken", the world changed.

SECRET: Separate Teams

Many organizations have a separate Maintenance Group vs. Development Group. Pros: Formal transfer of ownership. Cons: Maintenance team lacks the original knowledge.

KEY CONCEPT: Configuration Management

You must control access to the code library. If two programmers check out the same file and modify it, one's changes might overwrite the other's (The "Lost Update" problem). Tools like Git prevent this.
