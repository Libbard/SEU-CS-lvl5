The Modeling Process

Conceptual data modeling captures the overall structure of organizational data. It is independent of any Database Management System (DBMS).

Top-Down Approach

Derives the data model from an intimate understanding of the business nature.
"What are the subjects of the business?"

Bottom-Up Approach

Derives the data model by reviewing specific business documents (forms, reports).
"What data appears on this Invoice?"

Entity-Relationship Modeling

Entities

A person, place, object, event, or concept about which the organization wishes to maintain data.

  • Entity Type: Collection of entities (e.g., Employee).
  • Entity Instance: Single occurrence (e.g., John Doe).

Attributes

Properties or characteristics of an entity (e.g., Name, Address).

  • Candidate Key: Uniquely identifies an instance (e.g., ID).
  • Multivalued: Takes >1 value (e.g., Skill). {Curly Brackets}.

Relationships

An association between the instances of one or more entity types.

  • Degree: Number of entity types involved (Unary, Binary, Ternary).
  • Cardinality: Constraint on number of instances (1:1, 1:M, M:N).

Associative Entity

An entity type that associates the instances of one or more entity types and contains attributes that are peculiar to the relationship between those entity instances. Often used to resolve Many-to-Many (M:N) relationships.

Aggregation vs. Composition

  • Aggregation (Hollow Diamond): Weak "Part-of". Parts can exist independently. (e.g., Computer has a Monitor).
  • Composition (Solid Diamond): Strong "Part-of". Parts live and die with the whole. (e.g., Building has Rooms) .

The Exam Vault

Professor's Secrets & Trap Avoidance

TRAP: Cardinality vs Degree

Degree: The number of entity types that participate in a relationship (Unary, Binary, Ternary). Cardinality: The number of instances of entity B that can be associated with entity A (One, Many). Don't confuse "Binary Relationship" (Degree 2) with "One-to-Many" (Cardinality).

TRAP: The M:N Solution

"How do you implement a Many-to-Many relationship in a database?"
You CANNOT do it directly. You must create an Associative Entity (junction table) to break it into two 1:M relationships. Example: Student $\leftrightarrow$ Course becomes Student $\to$ Registration $\leftarrow$ Course.

SECRET: Attribute Types

Pay attention to attribute notation.
Underlined = Primary/Identifier Key.
{Curly Brackets} = Multivalued Attribute (e.g., Skills).
(Parentheses) = Composite Attribute (e.g., Address composed of Street, City).

KEY CONCEPT: The Diamond Rule

In UML Class Diagrams:
Solid Diamond (Composition): If the University is destroyed, the Departments are destroyed.
Hollow Diamond (Aggregation): If the Computer is destroyed, the Mouse/Keyboard can be reused elsewhere.
